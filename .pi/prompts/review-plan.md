## 审查要点

| 类别     | 检查内容                                                |
| -------- | ------------------------------------------------------- |
| 完整性   | 任务列表是否覆盖了 spec 的所有需求，没有遗漏            |
| 粒度     | 每个任务是否能在 15 分钟内完成、200k token 上下文内完成 |
| 顺序     | 任务的串行顺序是否合理，依赖关系是否正确                |
| TDD      | 是否遵循了 TDD 节奏（测试先行、最小实现、验证）         |
| YAGNI    | 是否包含了 spec 没有要求的多余任务                      |
| 可执行性 | 每个任务的描述是否足够清晰，执行者能理解要做什么        |

## 重点关注

- 任务描述过于模糊（如"实现整个 XX 模块"）
- 遗漏了 spec 中的某些需求
- 任务太大，需要进一步拆分
- 任务之间的依赖关系不明确

## 输出要求

你必须输出一个 JSON 对象（不要用 markdown 代码块包裹）：

如果通过：
{
"approved": true,
"recommendations": ["可选的改进建议"]
}

如果有问题：
{
"approved": false,
"issues": [
{ "taskIndex": 0, "issue": "具体问题", "suggestion": "修改建议" }
],
"recommendations": ["可选的改进建议"]
}

只输出 JSON，不要其他文本。
