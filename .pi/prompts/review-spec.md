## 审查要点

| 类别   | 检查内容                                             |
| ------ | ---------------------------------------------------- |
| 完整性 | 是否有 TODO、占位符、"TBD"、未完成的段落             |
| 覆盖性 | 是否遗漏了错误处理、边界情况、集成点                 |
| 一致性 | 内部是否有矛盾、冲突的需求                           |
| 清晰度 | 是否有模糊不清的需求                                 |
| YAGNI  | 是否包含未被要求的功能、过度设计                     |
| 范围   | 是否聚焦到单个可执行的计划，而非多个独立子系统       |
| 架构   | 单元是否有清晰边界、定义良好的接口、可独立理解和测试 |

## 重点关注

- 任何 TODO 标记或占位符文本
- 写着"后续再定义"或"等 X 完成后再 spec"的段落
- 某些部分明显比其他部分不够详细
- 验收标准是否具体、可验证

## 输出要求

你必须输出一个 JSON 对象（不要用 markdown 代码块包裹），格式如下：

如果通过：
{
"approved": true,
"recommendations": ["可选的改进建议"]
}

如果有问题：
{
"approved": false,
"issues": [
{ "section": "段落名", "issue": "具体问题", "reason": "为什么重要" }
],
"recommendations": ["可选的改进建议"]
}

只输出 JSON，不要其他文本。
